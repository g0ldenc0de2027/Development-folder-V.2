## Решение владельца

Локальная БЗ хранит сведения только своего проекта. Общая БЗ предназначена для общих норм/знаний и необходимой информации по всем проектам. Это прямое уточнение владельца от 2026-11-16; оно задаёт назначение баз, но само по себе не утверждает полный доступ всех агентов ко всем проектным данным.

## Цель

Устранить старую формулировку, будто общая БЗ содержит только обобщённый межпроектный опыт. Определить границу: локальная база остаётся детальным источником истины своего проекта; общая может хранить нужные проектные записи для портфельной работы при сохранении origin project ID, provenance, классификации, аудитории и действующих privacy/security ограничений.

## Критерии приёмки

1. В canonical и V2 одинаково сказано: локальная БЗ — один проект; общая — портфель по всем проектам, включающий общие знания и нужные проектные сведения.
2. Проектные записи сохраняют происхождение, scope, classification и audience; доступ фильтруется до выдачи, включая snippets/derived indexes, где механизм будет реализован.
3. Нет обещания автоматического зеркалирования, федеративного поиска, record-level ACL, publisher или обработки файлов, пока механизмы отсутствуют.
4. Секреты, персональные/закрытые данные и operational agent history не попадают в общую базу автоматически; текущие ограничения AGENTS остаются в силе.
5. V2 package version и policy-lock соответствуют новой канонической поставке; canonical module и V2 module побайтно совпадают.
6. Целевое требование обработки основных типов файлов явно отделено от текущей реализации; ни один документ не обещает существующий parser/ingestion.

## Ограничения

Эта задача меняет назначение и границу текстового правила. Она не реализует схему многопроектного каталога, классификатор, ACL, синхронизацию, ingestion, OCR/ASR или новый parser stack. Подтверждённое владельцем требование поддержки основных типов файлов остаётся целевым требованием для обеих БЗ и требует отдельного READY-спека до реализации.
