# Локальный просмотрщик проектов

## Быстрый старт

1. Используйте PowerShell 7.6 на Windows. Создайте файл `registry.json` в UTF-8 вне Git. В примере рабочая копия находится рядом с реестром в каталоге `checkout` и содержит папку `tasks`.

~~~json
{"projects":[{"id":"v2","name":"Development Folder V2","roots":["./checkout"]}]}
~~~

2. Запустите из любой папки. Введите полные пути к скрипту и реестру. Если V2 использует отдельные worktree, укажите путь к скрипту внутри выбранной рабочей копии, а в `roots` перечислите нужные checkout. При переносе обновите пути, сохранив ID проекта. Относительные пути разрешаются от каталога реестра.

~~~powershell
$viewer = Read-Host 'Полный путь к project-viewer.ps1 без кавычек'
$registry = Read-Host 'Полный путь к registry.json без кавычек'
pwsh -NoProfile -File $viewer -RegistryPath $registry
~~~

3. Откройте полный URL из вывода этого запуска в браузере на том же компьютере. URL содержит ключ локальной сессии. «Обновить» перечитывает источники. Ctrl+C останавливает просмотрщик.
4. Если URL не появился, проверьте диагностическое сообщение. При отсутствующем реестре исправьте путь. Если порт занят, добавьте `-Port 18765` или укажите другой свободный порт. После успешного запуска можно отдельно подключить очередь заданий, историю и снимок доказательств.


Карточка может содержать строки «Блокер:», «Следующее действие:», «Решение владельца: ожидается», а также явно подписанные PR_HEAD_SHA, PR_BASE_SHA, CI_HEAD_SHA и CI_BASE_SHA. Полный исходный текст всегда доступен для прочитанных версий.

## English quick start

Use PowerShell 7.6 on Windows. Create a UTF-8 registry outside Git and run the command above with absolute paths from any directory. Open the full session URL printed by that process. If no URL appears, check the registry path or retry with a free port such as -Port 18765. Refresh rereads sources. Ctrl+C stops the viewer. Keep the session URL private.

## Одна локальная очередь

Добавьте `queue` к тому же реестру. Укажите стабильное имя очереди и локальный каталог с подпапками `tasks`, `reports`, `accepted`. Относительный путь разрешается от файла реестра. Например:

```json
{
  "queue": {"id":"pilot","path":"./exchange"},
  "projects":[{
    "id":"v2","name":"Development Folder V2","roots":["./checkout"],
    "bindings":[{"taskId":"T-001","assignmentId":"PILOT-001"}],
    "ownerActions":[{"taskId":"T-001","text":"Проверить итог","requires":["PILOT-001"]}]
  }]
}
```

Привязки и указания необязательны. `requires` перечисляет ID привязанных к этой задаче заданий, по которым обе копии должны читаться и совпадать. Пустой список снимает условие сверки. Один ID задания может быть привязан только к одной задаче в реестре. Задания без привязки показаны отдельно. При недоступной очереди отображается последний снимок в пределах текущего сеанса. Отчёты до 1 МиБ отображаются как текст. Панель читает отчёты локально и не отправляет их во внешние сервисы.

## Панель хода разработки

Для календаря добавьте необязательный объект `timeline` к записи проекта в реестре:

~~~json
{
  "id": "v2",
  "name": "Development Folder V2",
  "roots": ["./checkout"],
  "timeline": {
    "timeZone": "UTC",
    "startDate": "2026-11-20",
    "stages": [
      {
        "id": "pilot",
        "name": "Пилот",
        "plannedDate": "2026-11-26",
        "taskIds": ["T-001"]
      }
    ]
  }
}
~~~

Используйте даты в формате `YYYY-MM-DD`. Дата старта, плановая и фактическая даты этапа необязательны. Для факта используйте поле `actualDate`. Часовой пояс определяет отметку «Сегодня». Нажмите название этапа, чтобы отфильтровать задачи. Доска и список используют общий поиск и фильтры.

Общий экран показывает задачи с полем «Решение владельца: ожидается». Из списка открывается карточка с действием и доступными доказательствами. Если источник отключён, отображается время последнего полного чтения. Данные за период доступны при подключённом файле истории. Если файл истории активности недоступен, панель сообщает об этом и продолжает показывать подтверждённые данные из журнала решений с отметками о неполном покрытии.

### Development overview

Add optional `timeline` metadata to a project as shown above. The time zone controls the Today marker. Dates use `YYYY-MM-DD` and may be omitted. Select a stage to filter tasks. The board and list share filters. The portfolio shows tasks waiting for an owner decision and the project view shows source freshness.

## Работа за период

Добавьте в запись проекта `"historyPath": "./v2-history.json"`. Путь считается от каталога локального реестра. Файл содержит UTF-8 JSON размером до 4 МиБ.

~~~json
{
  "schemaVersion": 1,
  "projectId": "v2",
  "events": [
    {"sourceId":"local","eventId":"e1","taskId":"T-001","type":"accepted","at":"2026-11-26T09:15:00+03:00"}
  ],
  "coverage": [
    {"type":"accepted","from":"2026-11-26T00:00:00+03:00","until":"2026-11-27T00:00:00+03:00"},
    {"type":"acceptance_revoked","from":"2026-11-26T00:00:00+03:00","until":"2026-11-27T00:00:00+03:00"}
  ]
}
~~~

Типы событий: `started`, `reported`, `reviewed`, `merged`, `added`, `accepted`, `acceptance_revoked`. Время указывается с UTC-смещением или суффиксом `Z`. Покрытие подтверждается отдельно по типу событий. Для полного итога принятых задач нужны интервалы и по приёмкам, и по отзывам приёмок. Конец интервала исключается. Без подтверждённого покрытия панель показывает известное число и пропуски.

Откройте проект, выберите период и нажмите «Показать отчёт». Кнопка «Скачать JSON» экспортирует показанный снимок, включая время чтения истории.

Для возраста текущего статуса укажите в карточке поле «Статус с:» с датой перехода. Для активного блокера укажите отдельно «Блокировка с:». Обе даты задаются в ISO 8601 со смещением. При отсутствии корректной даты карточка показывает «Нет даты».

## Доказательства по задаче

В объект проекта в локальном реестре добавьте `"evidenceSnapshotPath": "./evidence.json"`. Файл JSON в UTF-8 до 4 МиБ содержит `schemaVersion: 1`, `projectId` и массив `tasks`. Каждая запись содержит `taskId`, наблюдаемые `headSha` и `baseSha` и время `observedAt` в ISO 8601 со смещением. Используйте полные SHA в нижнем регистре.

Необязательные поля записи:

- `review` с `headSha`, `baseSha` и `status` (`approved` или `changes_requested`).
- `ci` с `headSha`, `baseSha`, `status` (`success`, `failure` или `pending`), `mergeResultSha` и массивом из двух `parents` в порядке base, head.
- `mergeSha` итогового коммита.
- `ownerAcceptance` со `status` (`accepted` или `revoked`) и временем `decidedAt`.

Обновляйте снимок из проверенных источников. Кнопка «Обновить» перечитывает файл. При сбое показывается последняя валидная копия текущего сеанса с отметкой устаревания. Панель проверяет согласованность данных снимка и показывает пару прежней проверки при изменении любой SHA. Для отчётов за период используется отдельный файл истории.

При открытии проекта сводка показывает текущий остаток по известным активным статусам и загружает «Сегодня». Подтверждённые приёмки и слияния отображаются раздельно на графике по дням. Выберите другой период, чтобы сравнить динамику. Если история неполная, числа за период включают только подтверждённые события.

## Взвешенная готовность

В запись проекта локального реестра добавьте объект `progress`. После правки перезапустите просмотрщик:

~~~json
{
  "schemaVersion": 1,
  "asOf": "2026-01-03T00:00:00Z",
  "decisionsComplete": true,
  "baselines": [{
    "projectId": "demo",
    "version": "v1",
    "approvedAt": "2026-01-01T00:00:00Z",
    "items": [
      {"id": "A", "criteriaVersion": "v1", "weight": 3},
      {"id": "B", "criteriaVersion": "v1", "weight": 5}
    ]
  }],
  "decisions": [{
    "projectId": "demo", "eventId": "accept-a", "itemId": "A",
    "scopeVersion": "v1", "criteriaVersion": "v1",
    "at": "2026-01-02T00:00:00Z", "type": "accepted", "evidenceId": "synthetic"
  }]
}
~~~

Замените демонстрационные ID и даты. У каждой следующей версии указывайте `previousVersion` и полную утверждённую раскладку весов. Для отзыва используйте отдельную запись `acceptance_revoked`. Ставьте `decisionsComplete` в `true` только после подтверждения полноты приёмок и отзывов до `asOf`. Доля готовности по утверждённому весу выводится отдельно от сводки статусов карточек.

## Стоимость разработки

Добавьте необязательный объект `cost` в запись проекта локального реестра, затем перезапустите просмотрщик. Значения ниже демонстрационные.

~~~json
{
  "schemaVersion": 1,
  "asOf": "2026-11-26",
  "scopeVersion": "v1",
  "planHours": [40, 50, 60],
  "planAiRub": [5000, 5000, 5000],
  "planAiUsd": [0, 0, 0],
  "planRubPerUsd": 100
}
~~~

Диапазоны задаются в порядке минимум, центральная оценка, максимум. Ставки `planRateRub` и `rateRub` по умолчанию равны 1 500 ₽/ч. Для прогноза укажите `remainingHours`, `remainingAiRub`, `remainingAiUsd`, `rubPerUsd`, `confirmedLaborRub`, `confirmedAiRub` и `confirmedAiUsd`. Явный ноль означает подтверждённое отсутствие расходов. Пропущенные значения показываются как недостающие данные. Курс указывается в рублях за 1 USD. Укажите `planExchangeRateDate` для исходного курса и `exchangeRateDate` для ручного курса прогноза, если дата известна.

Чтобы автоматически пересчитывать текущий прогноз, добавьте `"exchangeRateMode": "cbr"` в `cost` и уберите ручное значение `rubPerUsd`. Официальный курс Банка России загружается в фоне при запуске и проверяется раз в час. Снимок хранится рядом с выбранным реестром в файле с суффиксом `.usd-rub.json`. При сбое панель помечает курс как последний проверенный и показывает дату. Прогноз продолжает использовать это значение. Если проверенного снимка ещё нет, панель сообщает, что курс недоступен, и показывает доступные суммы в исходных валютах. Исходный план сохраняет `planRubPerUsd`. В режиме по умолчанию используются локальные значения курса.

To enable automatic USD/RUB for the current estimate, set `cost.exchangeRateMode` to `cbr` and omit the manual `rubPerUsd`. The Bank of Russia quote is fetched in the background on startup and hourly. The last verified quote is stored beside the registry with a `.usd-rub.json` suffix. An outage keeps the last verified quote and its effective date visible. Without a cached quote, the dashboard shows available native amounts. The original plan retains its pinned `planRubPerUsd`.

## Сценарный прогноз завершения

Когда расчёт невозможен, панель показывает «Прогноз не рассчитан» и причину. Например, может не хватать календаря, темпа или подтверждённого остатка. При достаточных данных панель показывает сценарный диапазон, а при подтверждённом завершении — дату завершения.

В записи проекта можно задать локальный объект `forecast`. Пример для объёма версии `v1`:

```json
{
  "schemaVersion": 1,
  "scopeVersion": "v1",
  "unitsPerDayLow": 1,
  "unitsPerDayHigh": 2,
  "workDays": ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday"],
  "daysOff": ["2026-12-31"],
  "planFinish": "2026-12-30"
}
```

Темп выражается в единицах веса утверждённого объёма за рабочий день. Дата расчёта берётся из среза готовности в часовом поясе проекта (UTC при отсутствии шкалы этапов). Даты календаря задаются в формате `YYYY-MM-DD`. Поля `notBefore`, `completedAt` и `unresolvedBlocker` позволяют указать известное ограничение, подтверждённую дату завершения и блокировку без срока.

Панель показывает сценарный диапазон и дату среза. При смене версии объёма обновите параметры прогноза для новой версии. При отсутствии подтверждённого остатка панель показывает причину, по которой даты недоступны.

## Журнал решений владельца

Для проекта, который подключает журнал, задайте относительный `decisionsPath` от реестра и явное соответствие `decisionTaskByItem` от ID результата к ID карточки. Базовые линии и дату среза `asOf` задавайте в `progress`. Приёмки и отзывы читаются из журнала. Данные о слияниях поступают из истории GitHub.

Панель подхватывает новый снимок по кнопке «Обновить». Если журнал недоступен, предыдущий снимок помечается как устаревший. Если покрытие подтверждено не полностью, шкала оставляет процент пустым. При отсутствии привязки результата к карточке детализация периода не засчитывает этот результат и показывает неполноту.

For journal-backed projects, set a registry-relative `decisionsPath` and map result IDs to task IDs in `decisionTaskByItem`. Supply baselines and a cutoff in `progress`. Use Refresh to load the next snapshot. Coverage gaps leave weighted progress unavailable.

## Динамика остатка

В разделе «Работа за период» график и таблица показывают вес остатка по календарным дням проекта. У каждой строки видны версия объёма, общий и принятый вес. Пунктир отмечает смену объёма, поэтому изменение плана видно отдельно от приёмок и отзывов.

Ряд использует зафиксированный срез `progress.asOf` и интервалы покрытия `accepted` и `acceptance_revoked` из истории. На даты после среза точки не строятся. После пропуска покрытия числовой остаток недоступен до восполнения истории. Для повторения старого расчёта сохраните прежний реестр и файл истории вместе. Текущий отчёт за период поддерживает до 90 дат графика.

Если состояние приёмок отдельно сверено после пробела, укажите в `progress.checkpoint` дату `asOf` с часовым поясом, ссылку на результат сверки `evidenceId` и `inputSha256`. Функция `Get-RemainingWorkInputHash` из `scripts/lib/ProjectRemainingWork.psm1` вычисляет хеш по ID проекта, дате сверки, версиям объёма и решениям, действовавшим на эту дату. Новые решения после среза не меняют хеш. Исправление старых входов требует повторной сверки. Снимок восстанавливает числовой остаток с даты сверки при полном покрытии последующих событий. Даты самого пробела сохраняются.

## Обновление истории слияний

Для рабочей ветки `main` запустите локальную сверку через установленный и аутентифицированный GitHub CLI:

```powershell
pwsh -NoProfile -File ./scripts/sync-project-merge-history.ps1 -HistoryPath 'ПУТЬ-К-ИСТОРИИ.json' -ProjectId v2 -Repository 'OWNER/REPOSITORY'
```

Команда читает все страницы закрытых PR, публикует в stdout число подтверждённых слияний, новые события и проверенную правую границу покрытия. Без `-Apply` файл истории сохраняется побайтно. С `-Apply` новые события и покрытие `merged` заменяются атомарно. Приёмки, отзывы и их интервалы сохраняются. Если новая ветка не содержит ID задачи в формате `task/T-NNN[-суффикс]`, сначала сверяется её привязка к карточке.

Запуски обновления одного и того же файла сериализуются локальным mutex. Изменения файла, обнаруженные с момента чтения до замены, останавливают запись. На время обновления другие программы должны только читать этот файл.

Для новой записи в `progress.baselines` укажите `reason` — краткое объяснение изменения утверждённого объёма, до 240 символов. Под графиком панель выводит каждое утверждение за выбранный период с локальным временем, предыдущей и новой версиями и изменением суммарного веса. Старые записи без поля причины читаются и отображаются с подписью «Причина не указана». При неполной истории приёмок отметка об утверждённом изменении сохраняется.
