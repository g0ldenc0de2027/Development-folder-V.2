# RULES и локальная база знаний: первый рабочий срез

Версия: 0.1.0. Дата: 2026-11-15. Автор: Codex, gpt-6.1-sol.
Статус требований: READY для перечисленного ограниченного среза T-004.
Реализация, проверки и приёмка: отдельно в карточке задачи.

## Основание и допуск

Владелец поручил написать RULES по согласованным решениям и сразу создать локальную БЗ,
затем явно выбрал новую реализацию в Development Folder V2. Эти указания от 2026-11-15
разрешают этот срез. READY не распространяется на весь продукт или будущий рой.

## Границы

Входит: рабочий регламент, Markdown-знания с JSON-каталогом; локальные check/search/get/context,
doctor подключения общей БЗ, capture в ignored inbox; документация и отрицательные проверки.
Исполнение: Windows, PowerShell 7.4+, стандартная библиотека, без новых зависимостей.

Не входит: автоматическое принятие знаний, издатель общих правил, миграция V1,
полноценный поиск общей БЗ, embeddings/SQLite, API/MCP/UI, dispatch роя,
аутентификация reviewer, защита от процесса с unrestricted shell той же учётной записи.
Публичный репозиторий содержит только разрешённые проектные знания.

Уточнение владельца: одновременно подготовить новую общую БЗ в указанном им месте.
Местоположение произвольное, в том числе другой диск; путь не является константой.
Входит создание пустого общего корпуса того же формата, исходного канона RULES и
project policy-lock с SHA-256. Редактируемый канон только общий; обновление копий пока
ручное, без authenticated publisher и автоматического контроля remote freshness.

## Требования и приёмка

| ID | Приоритет | Требование | Проверка |
|---|---|---|---|
| LKB-001 | P0 | RULES задаёт один источник нормы и честно описывает доступные механизмы | Ссылки существуют; будущие команды не выдаются за текущие |
| LKB-002 | P0 | Catalog связывает постоянный ID, проект, тип, статус, файл и SHA-256 | Изменение байтов обнаруживается; duplicate IDs/keys и неизвестная версия отклоняются |
| LKB-003 | P0 | Чтение ограничено knowledge/records и допустимыми обычными файлами | Traversal, absolute path, reparse point и oversized payload отклонены |
| LKB-004 | P1 | Get/search возвращают ID, статус, источники и точную ревизию | Кириллица и literal special characters; withdrawn исключён по умолчанию |
| LKB-005 | P0 | Context включает полные применимые RULES и выбранные знания с hashes | Недостаточный byte budget вызывает явный отказ, без обрезания правил |
| LKB-006 | P0 | Capture создаёт отдельное предложение, не меняя catalog | Уникальная публикация; неполный stage не считается готовым; secrets-подобный ввод отклоняется |
| LKB-007 | P0 | Config общей БЗ разрешается env, иначе локальный marker | Явно недоступный источник не заменяется; doctor не утверждает совместимость |
| LKB-008 | P1 | БЗ работает офлайн и после переноса проекта | Нет загрузок/телеметрии/сервисов; все canonical refs относительны |

LKB-002/003 предшествуют LKB-004/005. Capture не предоставляет права admission.
Проверки привязаны к этим IDs; CI запускает отдельный regression suite.

## Данные, доверие и безопасность

Канон содержания — Markdown; catalog — канон метаданных той же записи. Оба в Git.
JSON разобран строго: duplicate keys, неизвестные поля/версии и недопустимые типы — ошибка.
Проверка hashes подтверждает целостность, а не истинность или identity reviewer.
Все начальные записи имеют draft. Проверка/принятие знаний — отдельное действие главного ИИ
с evidence; CLI этого среза не выдаёт полномочий publisher.

Inbox — data/knowledge/inbox, вне Git. Это локальные рабочие предложения; их нужно
резервировать, если потеря недопустима. Сканер очевидных секретов не гарантирует очистку.
Реальные secrets/PII туда не записываются. Read/capture не обращаются к внешним моделям.
Reparse checks сокращают риск; не обещают OS sandbox или защиту от всех TOCTOU атак.

## Наблюдаемость, восстановление и эксплуатация

CLI: JSON stdout, диагностический код stderr, ненулевой exit при ошибке.
Вывод не содержит исходного текста ошибки парсинга/секрета. Captured receipt возвращает ID.
Канон восстанавливается из Git и отдельного backup незакоммиченного; inbox — отдельно.
Никакой автоматической activation старого restore или переноса live sessions.

## Решения и открытые вопросы

Решено: основной ПК/offline/переносимость, наружу только разрешённые данные;
GitHub-доноры дают идеи, реализацию пишем сами; общий канон правил выбран целевой архитектурой.
Первичная редакция правил готовится по текущему поручению и помещается в общую БЗ;
V2 получает побайтную копию и lock. Полноценный publisher и отзыв поставок остаются вне среза.
PowerShell здесь — ограниченный первый CLI, а не окончательный выбор ядра роя.
Открыто вне среза: publisher/lock протокол, backend индекса, adapters и OS isolation.
