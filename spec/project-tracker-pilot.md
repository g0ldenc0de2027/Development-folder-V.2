# Пилот единого трекера проектов

Статус — DRAFT, подготовлен к READY-review. База — PTR-001–PTR-005. Первый срез подключает одну явно выбранную очередь в режиме чтения.

## Данные и интерфейс

Реестр просмотрщика вне Git хранит ссылки на выбранную очередь и связи существующих заданий. Ключ задачи — projectId + taskId. Ключ задания — queueId + assignmentId. Одна задача может иметь несколько заданий. В пилоте связь задаётся явно в реестре. Позднее формат выдачи может передавать её непосредственно в карточке. Неподтверждённые связи не выводятся как установленные.

В карточке задачи отображаются исполнитель по данным задания, состояние обмена, отчёт и следующее действие. Состояние задачи берётся из её карточки. Состояние PR и CI отображается отдельно с доступными ссылками и ревизиями. Сданный отчёт без принятой копии ожидает проверки. Принятый отчёт сам по себе не закрывает проектную задачу.

Читать только явно подключённый источник. Задания и отчёты отображать как текст. При недоступности источника сохранить предыдущий снимок с отметкой времени и диагностикой. Различие SHA-256 сданной и принятой копий отображать как конфликт. Перед выдачей следующего действия учитывать подтверждённые данные и состояние источника. Явное следующее действие владельца сохраняет приоритет над подсказкой панели.

## Состояние приёмки и сверка копий

Формировать состояние по карточке задания и читаемым копиям в явно подключённой очереди. Принятая копия в accepted подтверждает зафиксированную приёмку, если она читается как допустимый Markdown. Статус Exchange сам по себе описывает наличие файлов. Сверка относится к SHA-256 байтов сданной и принятой копий. Подтверждать отсутствие файла только при доступном каталоге и однозначном ответе файловой системы. Ошибка доступа, чтения или декодирования даёт диагностику недоступности.

| Наблюдение | Отображение |
|---|---|
| Обе копии читаются и хеши совпадают | Отчёт принят, копии совпадают. |
| Принятая копия читается, сданная подтверждённо отсутствует | Отчёт принят, сданная копия отсутствует. |
| Принятая копия читается, сданная копия или её каталог недоступны | Отчёт принят, сверка недоступна. |
| Обе копии читаются и хеши различаются | Приёмка зафиксирована, конфликт копий. Показать обе версии и хеши. |
| Принятая копия подтверждённо отсутствует, сданная читается | Отчёт сдан, ожидает проверки. |
| Принятая копия недоступна при любом состоянии сданной | Приёмка не подтверждена. Показать диагностику и последнее наблюдение, если оно есть. |
| Принятая копия подтверждённо отсутствует, сданная недоступна | Статус задания неизвестен. Показать диагностику. Не предлагать проверку отчёта. |
| Обе копии подтверждённо отсутствуют | Задание выдано. |
| Очередь в целом недоступна | Последний известный статус со временем чтения, либо «Статус неизвестен» при отсутствии снимка. |

Читаемые отчёты доступны для просмотра как текст. Ошибка одного источника помечает устаревшими только его данные. Состояние проектной задачи сохраняет значение из её карточки.

## Следующее действие

Показать одно основное действие с причиной. Учитывать актуальные наблюдения и только те сигналы, которые относятся к текущему этапу задачи. Устаревшие данные показывать для контекста. Их недоступность может требовать восстановления доступа, если источник нужен для текущего перехода.

1. Явное указание владелец задаёт в локальном реестре для пары projectId + taskId. Запись содержит текст и список ключей заданий, для которых требуется подтверждённая сверка копий. Пустой список означает отсутствие этого условия. Указание имеет приоритет. Если для любого перечисленного задания сверка не подтверждена на актуальных данных, сохранить указание и показать причину блокировки. Текст карточек и отчётов не определяет такой список.
2. Если требуется решение владельца, показать «Получить решение владельца».
3. Если переход блокирует конфликт копий, недоступность нужного источника или явный блокер задачи, показать соответствующее действие. При нескольких сигналах этого уровня порядок такой: конфликт, недоступность, блокер.
4. Если доступный отчёт сдан и ожидает приёмки, показать «Проверить отчёт».
5. Иначе показать «Следующее действие не задано». Ссылки и явно записанные свидетельства PR, CI и ревью остаются в деталях задачи. Автоматические подсказки по проверкам отложены до появления источника актуальных данных по ревизиям.

Однотипные сигналы одинакового приоритета объединять с количеством и списком заданий, упорядоченным по queueId и assignmentId. Остальные сигналы доступны в карточке. Для закрытой задачи без явного действия подсказки перехода не формируются.

## Приёмка

| Проверка | Ожидаемый результат |
|---|---|
| Реальная задача и подтверждённая связь | Из карточки открывается соответствующий отчёт и виден следующий шаг. |
| Два задания на задачу | Обе записи видны со своими статусами и отчётами. |
| Задание без связи | Видно отдельно, без догадки по названию. |
| Одинаковые ID задач в двух проектах | Данные не смешиваются. |
| Недоступная очередь | Остальные источники обновляются. Данные очереди помечены устаревшими. |
| Разные хеши двух копий | Факт приёмки показан отдельно от конфликта. Обе версии доступны, сверка не подтверждена. |
| Принятая копия читается, сданная отсутствует или недоступна | Приёмка видна, отчёт открывается из принятой копии. Отсутствие и недоступность различаются. |
| Указание владельца и конфликт нужного отчёта | Указание остаётся основным, помечено заблокированным с причиной. |
| Два сданных отчёта равного приоритета | Одно действие «Проверить 2 отчёта» с устойчивым порядком. |
| Матрица читаемости копий | Перебрать читаемую, отсутствующую и недоступную копию независимо для reports и accepted (9 сочетаний). Для двух читаемых копий проверить оба результата сравнения хешей. |
| Указание без требования сверки | Конфликт остаётся видимым в карточке, указание не блокируется этим конфликтом. |
| Принятый отчёт и открытая задача | Статусы показаны независимо. |

Автоматическое назначение, приёмка из интерфейса, сетевой сбор данных и расчёт прогресса требуют отдельных срезов.
