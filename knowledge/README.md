# Локальная база знаний проекта

Формат 1, первый срез T-004. Начните с карты проекта и релевантных records.
Одна папка разработки — один проект; эта локальная БЗ содержит только его знания.
Общая БЗ накапливает ценное из локальных БЗ портфеля и принимает прямые записи владельца
на любую тему. В начале содержательной задачи агент проверяет обе БЗ; текущий CLI требует
два ручных запроса, объединённый поиск ещё не реализован.
После работы проверенные проектные знания сохраняются локально; ценное для портфеля
предлагается в общую после проверки provenance, свежести, audience и классификации.
Это не автоматическое зеркало, admission или publisher.

Ограничения безопасности: общей schema пока недостаточно для record-level ACL и
межпроектной авторизации. Не размещайте закрытые проектные данные в общей Git-backed БЗ,
полагаясь только на путь или права каталога. Внешний ИИ и GitHub являются egress;
передавайте только явно разрешённые данные.

Требуемая capability matrix обоих хранилищ включает текст и код, структурированные данные,
Office/PDF/email, изображения, аудио/видео, OCR/ASR, архивы и безопасное хранение
неподдержанных файлов как opaque. Сейчас индексируются только Markdown и JSON; для будущих
адаптеров статус stored-only не должен выдаваться за extracted или searchable.
Полный целевой workflow: spec/portfolio-kb-agent-workflow.md, DRAFT / NOT READY.
Обязательный регламент: [RULES](../rules/RULES.md).
Команды и ограничения: [руководство БЗ](../docs/local-knowledge.md).

- records/ — атомарные Markdown-записи; постоянные IDs и метаданные — catalog.json.
- [УРОКИ.md](УРОКИ.md) — обзор уроков со ссылками, без второго текста записей.
- [decisions/README.md](decisions/README.md) — обзор ADR.
- templates/record.md — заготовка записи, не принятый факт.

Тело и catalog — одна версия знания, хранятся вместе в Git. После изменения тела
обновляется contentSha256; прежнее review нельзя перенести на изменённый текст.
Изменение hash только восстанавливает целостность — не подтверждает содержание.
Начальные записи draft: без независимого подтверждения они не называются accepted.
Проверяемый список ограничен catalog; README/шаблоны не выдаются за проверенный корпус.

Предложения других агентов сохраняются capture в ignored data/knowledge/inbox.
Список заданий и оперативное общение не хранятся здесь как принятые знания.
