# Урок: отделять задачи до начала изменения

Наблюдение: совместная правка одного дерева затрудняет происхождение diff и review.
Причина: несколько исполнителей меняют пересекающиеся файлы без явного владельца.

Закрепление: отдельные task branch/worktree, baseline SHA, write-set и scope check
по полному diff. Общие контракты интегрируются раньше зависимых задач.
Один Git status не доказывает отсутствие посторонних committed изменений.

Приёмка: итоговый PR содержит только файлы задачи, а review связано с exact head.
Это урок-предложение; факт успешного enforcement проверяется на текущей автоматике.

Повторение: локальные `.work/` и `.manus/` заметки однажды попадали в шум статуса/сканеров,
а реальное имя task-ветки с суффиксом расходилось с более узким шаблоном hook.
Причина — локальные scratch-каталоги не были явно исключены, а branch grammar дублировалась
в нескольких слоях и в одном из них допускала только точный `task/T-NNN`.
Закрепление усилено: точные scratch-каталоги игнорируются, path-boundary regression
не даёт скрыть `.workflows`/`.manuscript`, secret scan сохраняет полный охват; центральный
scope guard проверяет ID и lowercase slug, а hook передаёт ему только ID.

Повторный корневой риск проявился в тестах: synthetic git fixture с TempRoot внутри
checkout вызвал `git init`, который повторно использовал внешний Git-каталог и передвинул
ref задачи. Защита: gate и fixture suite проверяют, что TempRoot расположен вне любого Git-репозитория
(worktree или bare), до любых записей; фикстура сравнивает исходные HEAD, refs, index и status до и после.
