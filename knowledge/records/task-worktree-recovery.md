# Урок: глобальный контроль состояния linked worktree

Дата: 2026-11-18
Статус: draft

## Наблюдение
Незакоммиченные изменения накапливались в отдельных ветках, хотя новая работа продолжалась в других worktree. Обычная проверка активной папки не показывала состояние соседних веток. Untracked и игнорируемые файлы, в том числе .vs, могли не попадать в привычный краткий статус; bare admin repository при этом не является рабочей копией и не принимает обычный git status.

## Причина
Процесс требовал начать чисто, но не запускал обязательный глобальный audit перед созданием задачи. Pre-commit и pre-push hooks проверяли отдельные свойства текущего commit/публикации, но не останавливали действие при грязном соседнем worktree. Создание worktree вручную было допустимо, однако проверка всех зарегистрированных копий и восстановление после interruption оставались процессными договорённостями. Поэтому не было раннего fail-closed сигнала, а отсутствие результата проверки можно было принять за чистое состояние.

### Вторичная причина: hook-контекст в regression harness
При реальном pre-push regression suite запускала fixture-команды git -C, наследуя GIT_DIR, GIT_WORK_TREE, GIT_INDEX_FILE, GIT_COMMON_DIR и GIT_PREFIX от hook. В результате setup тестового bare-репозитория воздействовал на настоящий локальный репозиторий: T-015 HEAD/index переключились на fixture, локальный main был заменён, и hook отказал до отправки. Backup показал, что все 66 путей последнего корректного T-015 commit 86e7f7f5bb3131f1c9fe96b04b92151a18cb85b9 на диске сохранили точные байты. После проверки резервной копии refs/HEAD/index восстановлены локально; remote не менялся. Этот случай показал, что изолировать Git-контекст должен и тестовый harness, а не только проверяемый production script.

### Повторная калибровка: 2026-11-18

Read-only-аудит T-015 выявил, что проверка только `git worktree list` не видит оставшийся физический каталог `.worktrees/T-NNN`, если Git его не зарегистрировал. Кроме того, удаление только пяти hook-переменных оставляло другие `GIT_*`, включая `GIT_CONFIG_COUNT`, способные подменить effective config или object store. Первая реализация очистки через `.NET SetEnvironmentVariable(name, $null, 'Process')` оставляла пустую переменную в Windows PowerShell; hook-context regression воспроизвёл `fatal: not a git repository: ''`. Исправление использует `Remove-Item Env:` с точным восстановлением исходного окружения.

Закреплено: аудит сравнивает физические каталоги `.worktrees/T-NNN` со списком зарегистрированных worktrees и блокирует orphan, не изменяя данные; reparse point на корне `.worktrees` блокируется; fixture и production Git subprocesses очищают все `GIT_*`. Новые тесты покрывают пустой production quarantine, missing/prunable worktree, orphan-каталог, несоответствие ID ветки и каталога, config injection и hook context. Целевой suite прошёл 17/17; это доказывает поведение synthetic fixtures на проверенной редакции, но не исключает обход локальных hooks или гонку с внешним процессом.

### Повторная калибровка после независимого ревью: 2026-11-18

На PR #11 Antigravity проверил точный head be8860cb8f4ecfa1111420ac9ffe50c344659f57 и дал APPROVE с двумя low-наблюдениями; DeepSeek сообщил APPROVE без уязвимостей для той же пары SHA. Эти отзывы относятся только к тому head, до исправлений ниже.

1. Безопасный GIT_PREFIX=config/ для вызова Git из вложенной папки отклонялся как неожиданный. Адресная проба прошла после проверки, что префикс относительный, без компонентов . или .., реально существует и остаётся внутри текущего worktree; traversal ../outside/ остаётся заблокирован.
2. Точный quarantined-файл с кириллическим именем не совпадал с git status --porcelain, когда effective core.quotepath=true возвращал C-escaped путь. Status-вызовы теперь явно используют core.quotepath=false; manifest и сравнение путей остаются точными.

Во время добавления второй регрессии был замечен отдельный дефект контроля тестов: некорректно разделённый блок пропустил исходный pre-push case, но suite завершилась с кодом 0. Оба runner теперь сравнивают число реально выполненных cases с явным ожидаемым count (25 identity, 19 worktree) до печати PASS. Путь для scratch тоже должен быть коротким: глубокий temp root вызвал Windows Filename too long / GIT_DIR too big, поэтому такой прогон считается ошибкой окружения и не свидетельствует о дефекте проверяемого кода.

Targeted regression suites на исправленном кандидате прошли 25/25 и 19/19. Полный gate и новые hosted/review evidence обязаны быть привязаны к итоговому commit; изменение head делает оба прежних AI-отзыва устаревшими. Запись остаётся draft, автоматического принятия урока нет.

## Закрепление
- scripts/task-worktree-audit.ps1 -Mode Audit проверяет все зарегистрированные worktree, физические каталоги `.worktrees/T-NNN`, tracked, staged, unstaged, untracked, missing/prunable записи, связь task ID с веткой и игнорируемые .vs. Вложенные Git-вызовы временно удаляют все process `GIT_*` и восстанавливают исходное окружение.
- pre-commit повторяет глобальный audit и допускает только staged write-set текущего worktree; pre-push требует чистое состояние и повторяет audit.
- Regression suite проверяет чистые/грязные и отсутствующие worktrees, orphan-каталоги, mismatch ID, ignored .vs, точный synthetic quarantine, пустой production quarantine, hooks и изоляцию Git environment/config в fixtures и production subprocesses.
- Создание новой задачи начинается только после успешного audit. После interruption сначала обновляется handoff и продолжается исходная задача; автоматических reset, clean, stash или удаления нет.

На 2026-11-18 семь исходных raw-файлов были помещены в архив Development-Folder-V2_T-013-source-snapshot-2026-11-18_91bb56d5.zip и повторно проверены: archive SHA-256 734f27b8027e4a0aaa2f1aeca5868ba242249766fca26e975fcb718c60602d99, Canonical Bundle Manifest Format 1 SHA-256 91bb56d5de1822cfb64a9fad0270c83d41d5b00c110e6740d2804c9e96c2d4f3. Backup ref backup/2026-11-18-T013-source-base указывает на исходный HEAD 88342060af7c6c18a163d3b6fa6727ab5c17fd7e. После явного разрешения владельца исходный worktree возвращён к этому же HEAD и проверен как чистый; commits и ветка не переписывались. Это сохраняет данные снимка, но не утверждает, что неизвестное историческое авторство исправлено.

## Ограничения
Локальные Git hooks можно отключить или обойти; это снижает риск случайного продолжения поверх грязных деревьев, но не является абсолютной защитой. Аудит — снимок состояния: конкурентное изменение worktree после проверки возможно, поэтому pre-push повторяет проверку. Никакой автоматической очистки не выполняется.
