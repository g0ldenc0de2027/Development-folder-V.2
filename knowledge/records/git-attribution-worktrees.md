# Урок: безопасная Git identity в linked worktrees

Наблюдение: локальные задачи в linked worktrees получили неправильную общую identity, а bare admin repository с общим `core.bare=true` мешал обычным операциям вроде `git status` в связанных рабочих копиях.

Причина: `git config --local` меняет общий конфиг worktree-семейства. Идентичность должна быть worktree-scoped через `extensions.worktreeConfig`; `core.bare` тоже нельзя без разбора наследовать из общего конфига. Явный `git commit --author` может изменить metadata уже создаваемого commit, поэтому один pre-commit не гарантирует перехват.

Закрепление: до commit проверять authenticated GitHub account и effective identity, сохранять имя/email только в config.worktree, проверять реальный Git hook и каждый outgoing commit до отправки. Bare-admin `core.bare=true` переносить в config.worktree самого bare-root только после проверки структуры и регистрации worktree; текущей linked worktree задавать `core.bare=false`. Неоднозначный common `core.worktree` блокировать. После некорректного commit не переписывать историю: сохранить refs и решать отдельной recovery-задачей.

Историческое уточнение T-015 от 2026-11-18, зафиксированное до проверки опубликованной ревизии: Git вычисляет author/committer до запуска pre-commit. Поэтому успешная автокоррекция config не может безопасно продолжить ту же попытку: hook должен завершить её отказом, затем агент повторяет commit отдельной командой после verifier. Hook-context допускает только canonical index или Git temporary index в точном gitdir; приблизительное совпадение имени (например, любая строка вместо точки в `next-index-N.lock`) запрещено. Read-only recovery source T-013 нужно блокировать как исходный и как целевой branch ref, иначе его можно опубликовать под другим именем.

Исторические источники и точные ревизии: владелец, задача T-015 (2026-11-17); независимые замечания Xiaomi MiMo и Antigravity по PR #11; синтетические regression cases T-015 на HEAD `bc767fbfad46780a464ac83b5755819eada5af3e` (31/31 на локальном рабочем diff 2026-11-18, пока не hosted/reviewed); официальный Git `git-worktree` и `git-config`.

Область применимости и ограничения: Git linked worktrees на Windows в поддерживаемой среде проекта. Синтетические regression cases проверяют механизм, но сами по себе не подтверждают физическое авторство и не защищают от отключения локальных hooks.

Как проверить: запустить `pwsh -NoLogo -NoProfile -File tests/git-identity-regressions.ps1`; затем выполнить проектный quality gate в точной task worktree и проверить `git status` в затронутых worktrees. Результат 31/31 относится к незакоммиченному diff от 2026-11-18. На main `7da6c0f4f4367ec9465eafd16acf249dc9a0e277` полный Windows gate от 2026-11-21 подтвердил 32/32 Git-identity регрессий. [Hosted run 44901331572](https://github.com/g0ldenc0de2027/Development-folder-V.2/actions/runs/44901331572) подтверждает прохождение gate на том же SHA. Повторите проверку после изменения hooks, правил авторства, Git for Windows или конфигурации рабочего дерева.
