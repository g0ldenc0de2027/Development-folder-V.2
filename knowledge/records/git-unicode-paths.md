# Урок: не зависеть от кодовой страницы консоли при чтении Git-путей

**Статус:** подтверждено локальной регрессией, 2026-11-19

**Контекст:** V2, `scripts/verify-task-scope.ps1`, PowerShell 7.6.10, Windows 11.

## Наблюдение

Scope guard ошибочно отклонял допустимый Unicode-путь `spec/ТЗ.md`, когда PowerShell запускал Git с кодовой страницей CP866. Та же фикстура проходила при обычной UTF-8 среде. Это был ложный отказ для корректной зоны задачи.

## Причина

Результат native Git декодировался с текущей кодовой страницей консоли. Проверка корректности scope зависела от локальной настройки машины, а обычный тест покрывал только UTF-8.

## Закрепление

На время каждого вызова Git scope guard задаёт UTF-8 для декодирования native output и восстанавливает прежнюю кодировку в `finally`. Регрессия запускает проверку с Unicode-путём, реальным linked-worktree Git-контекстом и CP866; suite также проверяет полный scope, чистоту дерева и неизменность HEAD, refs, index и status исходного репозитория.

## Граница доказательства

Локальный полный gate и pre-push прошли на содержимом, опубликованном как PR head `e8653345c5a62382be02bf8957e459a4def28e6a`. Hosted run [#44402452200](https://github.com/g0ldenc0de2027/Development-folder-V.2/actions/runs/44402452200) прошёл на merge-result `66c80a08d0f4f8569efd0c6e944a9b0dc8ba3cc0` с точными родителями base/head. Независимый review этого head ещё требуется. Доказательство не распространяется на неподдерживаемые версии PowerShell или другие ОС.
